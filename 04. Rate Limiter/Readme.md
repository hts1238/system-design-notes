# Глава 4: Проектирование ограничителя частоты запросов

## Введение
В этой главе рассматриваются проектирование и реализация ограничителя частоты запросов — компонента системы, регулирующего интенсивность трафика от клиентов или сервисов. Ограничители частоты запросов необходимы для предотвращения злоупотреблений, снижения затрат и обеспечения стабильной работы серверов. Например, с их помощью ограничивают публикации, создание аккаунтов и получение наград.

## Преимущества ограничения частоты запросов
- **Защита от DoS-атак:** блокировка избыточных вызовов, чтобы предотвратить исчерпание ресурсов.
- **Снижение затрат:** ограничение ненужных запросов для уменьшения расходов на серверы.
- **Предотвращение перегрузок:** фильтрация избыточных запросов для стабилизации производительности серверов.

## Шаг 1: Понимание задачи
### Ключевые возможности
- Серверный ограничитель частоты запросов к API.
- Поддержка нескольких правил ограничения.
- Работа с крупномасштабными системами в распределённых средах.
- Возможность реализации в виде отдельного сервиса или кода на уровне приложения.
- Уведомление пользователей об ограничении запросов.

### Требования
- Точное ограничение частоты запросов.
- Минимальная задержка.
- Низкое потребление памяти.
- Поддержка распределённой работы.
- Понятная обработка исключений.
- Высокая отказоустойчивость.

## Шаг 3: Алгоритмы ограничения частоты запросов
### 1. Token Bucket (корзина токенов)
<div style="margin-left:2rem">
  <img src="./images/token-bucket.png"  alt="Алгоритм Token Bucket" width="550">
</div>

- **Описание:** токены добавляются в корзину с фиксированной скоростью; каждый запрос расходует один токен.
- **Параметры:** размер корзины и скорость пополнения.
- **Преимущества:** простота реализации, экономное использование памяти, поддержка всплесков трафика.
- **Недостатки:** параметры нужно тщательно настраивать.



### 2. Leaking Bucket (протекающая корзина)
<div style="margin-left:2rem">
  <img src="./images/leaking-bucket.png"  alt="Алгоритм Leaking Bucket" width="550">
</div>

- **Описание:** обрабатывает запросы с фиксированной скоростью, используя очередь FIFO.
- **Преимущества:** экономное использование памяти, стабильная скорость обработки.
- **Недостатки:** всплески трафика могут задержать недавно поступившие запросы.
  

  Пример: https://github.com/uber-go/ratelimit



### 3. Счётчик с фиксированным окном
<div style="margin-left:2rem">
  <img src="./images/fixed-window-counter.png"  alt="Счётчик с фиксированным окном" width="550">
</div>

- **Описание:** делит время на фиксированные интервалы и ограничивает запросы с помощью счётчиков.
- **Преимущества:** простота и эффективность в определённых сценариях.
- **Недостатки:** всплески трафика на границах окон могут привести к превышению лимита.

- Внезапный всплеск трафика на границах временных окон
может пропустить больше запросов, чем разрешено квотой.

  <img src="./images/fixed-window-issue.png"  alt="Проблема фиксированного окна" width="550">


### 4. Журнал скользящего окна
<div style="margin-left:2rem">
  <img src="./images/sliding-window-log.png"  alt="Журнал скользящего окна" width="550">
</div>

- **Описание:** отслеживает временные метки, чтобы поддерживать скользящее временное окно.
- **Преимущества:** точное ограничение частоты запросов.
- **Недостатки:** высокое потребление памяти.
  


### 5. Счётчик скользящего окна
<div style="margin-left:2rem">
  <img src="./images/sliding-window-counter.png"  alt="Счётчик скользящего окна" width="550">
</div>

- **Описание:** сочетает методы фиксированного окна и журнала скользящего окна, сглаживая всплески.
- **Преимущества:** экономное использование памяти, обработка всплесков трафика.
- **Недостатки:** приблизительные расчёты могут быть не вполне точными.

## Дополнительные аспекты
### Распределённые среды
- **Проблемы:** состояния гонки и сложности синхронизации.
- **Решения:** используйте блокировки, Lua-скрипты или отсортированные множества в Redis. Для синхронизации применяйте централизованные хранилища данных.

### Оптимизация производительности
- Развёртывание в нескольких центрах обработки данных для снижения задержки.
- Модели согласованности с eventual consistency для синхронизации.

### Мониторинг
- Регулярно анализируйте эффективность алгоритма и при необходимости корректируйте правила.
